# DeviceLib v1.1.1 - Enhanced Memory Management & Stability

**Release Date:** July 23, 2025  
**Release Type:** 🛡️ Stability & Bug Fixes  
**Compatibility:** ✅ Fully backward compatible  

## 🚀 What's New

### 🧠 Enhanced Memory Safety
Revolutionary memory management improvements that prevent leaks and crashes in long-running IoT applications.

- **Automatic Timer Cleanup** - Objects now properly clean up their timer resources when destroyed
- **Cross-Platform Destructors** - Works seamlessly on both ESP32 and ESP8266
- **Zero Memory Leaks** - Perfect for applications that run 24/7 or frequently create/destroy objects

### 🎛️ Advanced Callback Management
New methods for dynamic applications that need to change behavior at runtime.

```cpp
GenericButton btn(10);

// Add multiple callbacks
btn.onClick(callback1);
btn.onDoubleClick(callback2);
btn.onLongClick(callback3);

// Dynamic mode switching
btn.clearCallbacks();           // Remove all callbacks
btn.removeCallbacks(CLICK);     // Remove specific event callbacks

// Configure new behavior
btn.onClick(newModeCallback);
```

### 🔍 Better Error Diagnostics
Enhanced debugging capabilities for easier troubleshooting.

- **Detailed Timer Errors** - ESP32 timer creation failures now show specific error codes
- **Null Pointer Safety** - Defensive programming prevents crashes from race conditions
- **Better Logging** - More informative debug messages

## 🛡️ Stability Improvements

### Memory Leak Prevention
**Problem Solved:** Previous versions could leak memory when objects were frequently created and destroyed.

**Before:**
```cpp
// This pattern could cause memory leaks
for (int i = 0; i < 100; i++) {
    GenericButton btn(10);
    btn.onClick(callback);
    // Timer resources might not be cleaned up
}
```

**After v1.1.1:**
```cpp
// Now completely safe - automatic cleanup
for (int i = 0; i < 100; i++) {
    GenericButton btn(10);
    btn.onClick(callback);
    // Timer resources automatically cleaned up ✅
}
```

### Cross-Platform Reliability
- **ESP32**: Proper `esp_timer` deletion prevents handle leaks
- **ESP8266**: Correct `Ticker` detachment prevents timer conflicts
- **Both**: Enhanced null pointer checks prevent crashes

### Thread Safety Improvements
- Timer operations now check for null pointers before execution
- Safer callback execution during object destruction
- Better handling of race conditions in multi-threaded scenarios

## 💻 For Developers

### No Breaking Changes ✅
All existing code continues to work without any modifications required.

```cpp
// All existing patterns still work exactly the same
GenericButton btn(10, INPUT_PULLUP, LOW);
btn.onClick([]() { Serial.println("Clicked!"); });
btn.onLongClick([]() { Serial.println("Long press!"); });
```

### Optional New Features
Take advantage of new capabilities when needed:

```cpp
// Use new callback management features
btn.clearCallbacks();                    // New in 1.1.1
btn.removeCallbacks(BUTTON_EVENT_CLICK); // New in 1.1.1

// Enhanced error handling automatically active
// No code changes required
```

### Compiler Warnings
Deprecated methods now show helpful compiler warnings:

```cpp
btn.onActive(callback);   // ⚠️ Warning: Use onPress instead
btn.onInactive(callback); // ⚠️ Warning: Use onRelease instead
```

## 📦 Upgrade Instructions

### Step 1: Simple Replacement
Replace your existing DeviceLib files with v1.1.1. No code changes required.

**PlatformIO:**
```ini
[env:your_board]
lib_deps = 
    nht173/DeviceLib@^1.1.1  # Update version
```

**Arduino IDE:**
1. Remove old DeviceLib folder
2. Install v1.1.1 from library manager or ZIP

### Step 2: Test Your Application
Run your existing code - everything should work exactly the same but more reliably.

### Step 3: Optional Enhancements
Consider using new features for dynamic applications:

```cpp
// Add this for applications with mode switching
void switchToSetupMode() {

    configButton.onClick([]() { enterConfigMenu(); });

}
```
